# Repository review - 2026-10-22

This pass followed the main/preload/renderer message path, connection lifecycle, topic models, persistence hooks, publishing, recording/playback, simulation, UI controls, and build configuration. It fixes verified defects and establishes regression coverage; it is not a claim that all remaining behavior is production-ready.

## Fixed in this pass

| Area | Defect and resulting behavior |
| --- | --- |
| Connection lifecycle | Early socket close left connect promises pending; retry could leak clients; cancellation left timeouts alive. Attempts now settle and clean up, and concurrent connects share one client. |
| MQTT settings | MQTT 5 `clean` was replaced by an unsupported option; zero keepalive/reconnect values, empty wills, user properties, and subscription IPC properties were lost. These settings now reach MQTT.js. |
| Reconnect | The configured reconnect period was ignored. It is applied after the initial successful connection; configured subscriptions are restored and denied SUBACKs are rejected. |
| IPC and desktop | Window recreation duplicated forwarding listeners. Forwarders register once; IPC checks the sending window/frame, navigation and popups are blocked, and the renderer is sandboxed with a CSP and local icon fonts. Duplicate packet payload transfer was removed. |
| Topic identity | Filtering empty topic levels merged distinct MQTT topics. Leading, trailing, and repeated slashes now remain distinct. |
| Counts and rates | Parent topics double-counted descendants and clearing a parent's direct history subtracted descendant counts. Counts are separated; rates use time buckets independent of the 300-message buffer, decay while idle, and cache subtree totals. |
| History | Timestamp-only React keys collided during bursts; byte limits counted characters and accepted oversized entries. IDs are now monotonic per connection, including after topic eviction or clearing. Buffers count raw payload bytes, and connection budgets bound retained encoded storage, messages, nodes and depth. Least recently received topics are evicted with visible counters; affected message views refresh. Oversized payloads are not retained in the latest-message cache, and tree snapshots contain bounded previews. |
| Binary payloads | Invalid UTF-8 previously lost bytes on arrival. A shared UTF-8/base64 contract now preserves bytes across MQTT, IPC, history, recording, JSON/CSV export, import and republishing. Text/hex inspection is available; binary copies and exports explicitly use base64. Legacy recordings default to UTF-8. |
| Saved connections | Refresh replaced all saved profiles with the subset already known to the MQTT service. Refresh now merges status into saved profiles. Loading state before persistence also avoids overwriting saved settings during mount. |
| Disconnect behavior | Disconnects and errors erased topic trees. History remains available for inspection after disconnect. |
| Recording | The panel received a permanently empty array. It now captures live events for its source broker, batches UI counters, retains same-timestamp bursts, and stops with a visible notice at its capture limit. |
| Recording persistence | Saved recordings now use a versioned main-process disk library instead of localStorage. Writes flush a temporary file before atomic replacement, serialize mutations, and reject stale revisions. Legacy libraries migrate by content fingerprint, so retries do not duplicate data and different renderer origins are handled independently. Failed loads preserve storage; failed saves remain available in memory with retry/export. One app instance owns each user-data directory. |
| Playback | Publishing ran inside a React state updater and scheduled every message at once. Playback uses one timer, performs side effects outside state updates, defaults to preview, and cancels scheduled work on source/filter changes. |
| Simulation | Slow publishes overlapped, previews differed from live generation, and duplicate names could overwrite payload fields. Individual signals now have topics and schedules with synchronized clocks, offsets, fixed or random intervals and publish probabilities. Each signal permits one pending publish and drops busy ticks. Existing combined-topic devices retain completion-based scheduling. Both modes isolate connection state. Shared validation and generators preserve zero settings and raw random-walk state. Live samples no longer rewrite saved settings. Presets, five new numeric generators, three-cycle waveform charts with labeled axes, QoS/retain and a full-width device editor make devices easier to construct and inspect. Signal cards, selects, buttons and interval sliders reuse shared design tokens and control styles. Legacy payload shapes remain compatible. |

| Live navigation | Topic search includes collapsed branches without changing saved expansion. Siblings keep first-seen order, and virtualized scrolling anchors existing rows as branches grow. Message lists preserve the visible message and pixel offset while pinned, resume following at the top in either sort order, and order same-timestamp bursts consistently. Signal charts are smaller in both the editor and overview. |
| Imports | Malformed recording timestamps and payloads could break rendering. Imports are size-limited and validated; message counts are recomputed. Basic schema validation now handles null, arrays, nested values, and required properties. |
| Tooling | Added regression and desktop smoke tests, upgraded Electron/build/test tools, updated Windows signing configuration, refreshed dependencies, and replaced obsolete build instructions. |

## Remaining priorities

1. **Application memory and streaming capture.** Browsing history now has Compact (32 MiB / 5,000 nodes) and Larger (64 MiB / 20,000 nodes, default) profiles, a shared 128 MiB estimated cache cap across connections, and a 50,000-topic model regression. Both profiles retain the 50,000-message and 128-level limits per connection. Payload trimming preserves topic identity/counts/rates; metadata eviction protects selected paths and up to eight pinned paths per connection. Protected payloads can still expire. This is not a process-memory cap: IPC queues, runtime overhead, publishing drafts and recordings remain outside it. Saved recordings live on disk, but the renderer still loads the whole library (capped at 64 MiB / 1,000 recordings), and each save rewrites that library. Transport backpressure and paged disk history are implemented. Add lazy recording loading, streaming capture and checkpointed migration. Measure process memory and input latency during long-running wildcard subscriptions to tune defaults.
2. **Payload tooling.** Binary round trips and text/hex inspection are implemented. Raw file import/export and binary last-will editing remain useful additions; last wills currently accept text. Text previews of invalid UTF-8 show replacement characters, while base64 exports preserve the bytes. Full message inspection is capped at 4,096 bytes to avoid rendering huge payloads; exports retain all stored bytes.
3. **Credential storage.** Saved connections include passwords and private keys in localStorage. Move secrets into main-process storage using OS-backed encryption and migrate existing profiles without dropping credentials. Avoid persisting volatile connection state alongside secrets.
4. **Typed and validated IPC.** `ConnectionConfig` and event payloads still use broad shapes; `mqtt-connection-manager.js` is outside strict JS checking. Add per-event discriminated types and runtime validation for topic names, configuration ranges, QoS, and payload encoding. Test malicious/malformed inputs at the IPC boundary.
5. **Storage and schema validation.** Recording persistence no longer uses localStorage. Disk exhaustion or the library limit is reported with retry/export; active capture checkpoints and library backup/recovery tooling remain open. Imported templates and saved UI/device settings still need complete shape validation. Template validation covers only a subset of JSON Schema and does not resolve `$ref`, combinators, or all constraints. Use a standards-compliant validator if that feature is required.
6. **Timing and backpressure.** Playback waits for each publish and can drift with broker acknowledgement latency; resuming restarts the current inter-message delay. Individual simulator signals now follow monotonic deadlines and skip missed or busy ticks, keeping fixed periods aligned across signals. Combined-topic mode waits for completion before scheduling the next interval. Neither mode builds a backlog. Aggregate transport limits, stalled acknowledgements and broker-disconnect stress tests under QoS 1/2 traffic remain open.
7. **UI consistency and accessibility.** Selected metadata now refreshes from the tree, and highlighting follows the remembered selection across connection changes. Publishing drafts follow selection identity rather than every metadata update. Nested div/button controls still need broader keyboard/focus work. The simulator and header tabs now fit the minimum 800px window width; other panels need broader responsive checks. Notifications overlap header controls during bursts. Topic search and anchored scrolling are implemented; message-content search and a resizable payload inspector remain open.
8. **Reload/shutdown recovery and protocol coverage.** Live recordings are in memory until stopped. Refreshing or closing the renderer can lose an active capture; renderer reload also needs an explicit connection reconciliation policy. Add durable checkpoints and tests with real TLS/client certificates, WebSocket paths/headers, MQTT 5 session expiry, denied authentication, QoS 2, and reconnecting persistent sessions.

### 2026-10-23: bounded message delivery

Incoming IPC now uses acknowledged batches, an aggregate queue bound and renderer time slices. Control events bypass batches; unused per-publish payload forwarding was removed. Each transport message carries its original receive timestamp, session UUID and monotonic sequence. Overflow and reload-abandoned/unconfirmed messages have visible counters; recordings stopped by a detected gap keep a warning through save/export/import. This limits app-owned delivery queues, not MQTT parser buffers or process RSS. Full throughput/latency measurements and worker-backed durable capture remain open.

Validation: 84 tests, typecheck, lint and the built Electron smoke test, including the 5,500-topic pressure case. The installed Electron 45 runtime also passed a worker-thread `node:sqlite` binary round-trip spike (SQLite 3.53.4); storage implementation and packaged validation are separate follow-ups.

### 2026-10-23: paged disk history

A main-managed worker now owns SQLite via the installed Electron/Node runtime. Independent bounded ingestion preserves history even if renderer delivery falls behind. The Logging workspace can browse fixed snapshots beyond 300 messages, search stored topic paths, opt into restart persistence and clear an exact topic. Raw payloads and MQTT 5 properties survive transactions and restart. Default session cleanup handles normal exit and the next startup after a crash. Retention uses a 256 MiB estimate, a 24-hour query age limit with incremental removal, and a 512 MiB database ceiling plus rollback-journal overhead. SQLite's page cache is 8 MiB. Rollback journaling was chosen because one worker serializes all reads and writes; WAL is not needed for this first implementation.

Remaining limits: the live tree is still a separate bounded cache; export is page-scoped; recording capture/library migration is not implemented; gap counters are per-run, not a durable journal of all capture failures; long-running RSS/input-latency benchmarks and installer upgrade checks remain open. Obsolete renderer page results are ignored and worker requests are bounded; full search cancellation still needs work.

Validation: 92 tests plus typecheck and lint pass. Built Electron coverage browses 650 messages through the real source/topic/page controls, checks invalid cursors and scoped deletion, and retains the earlier pressure tests. The worker suite passes under Node, Electron 45, and the Windows packaged executable using the worker inside `app.asar`; it verifies binary/MQTT 5 round trips, restart persistence, crash-session cleanup and corruption reporting. `npm run pack` passes. This validates unpacked Windows packaging, not an installer upgrade or sustained-load benchmark.
